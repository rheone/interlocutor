# 08 - Convert NSubstitute-mocked transaction tests to real in-memory NHibernate integration tests

**What to build:** The tests that exercise `UnitOfWorkBehavior`'s/`NHibernateUnitOfWork`'s transaction lifecycle currently mock the entire `ISession`/`ITransaction` interface with NSubstitute, then hand-wire boolean side effects (`transactionBegun`/`transactionActive`, toggled inside `.Returns(...)`/`.When(...).Do(...)` callbacks) to simulate what a real NHibernate session already does for free when you call `BeginTransaction()`/`CommitAsync()`/`RollbackAsync()`. That simulation is built directly on top of the now-obsolete `ISession.Transaction` property (ticket 07 fixes production code's own use of it) - continuing to mock it, even behind a suppression, means these tests keep exercising a hand-rolled approximation of NHibernate's transaction semantics rather than the real thing, and will need re-simulating again the next time NHibernate changes this surface. Replace the mocking with a real, lightweight in-memory NHibernate session instead, following the shared-cache-mode mechanism `TutorialProject/TodoTasks.Api/Persistence/TodoTasksSessionFactory.cs` already established for exactly this problem (one anchor connection kept alive per fixture instance, SQLite shared-cache mode, no separate migration step).

Affected files:

- `tests/Interlocutor.Persistence.NHibernate.Tests/SharedSessionIntegrationTests.cs` - already declares a nested `Widget` test entity for exactly this purpose, currently unmapped and used only as a plain object NSubstitute records `SaveAsync`/`FlushAsync` calls against. Give it a minimal mapping (FluentNHibernate or a plain `Configuration.AddXmlString`) and a real session factory, so the test proves repository + unit-of-work + behavior share one session/transaction via an actually-persisted row, not a mocked call-count assertion.
- `tests/Interlocutor.Persistence.NHibernate.Tests/UnitOfWorkBehaviorTests.cs` - the transaction-lifecycle tests built on `CreateStubbedSession()` (begin/commit/rollback, `IsDirty()`-triggered write, cancel-triggered rollback). Convert the ones that are genuinely testing transaction mechanics; a test that only cares about a classifier decision or a call count unrelated to real transaction state can stay lighter-weight if converting it wouldn't add real coverage - judgment call, note the reasoning either way.
- `tests/Interlocutor.DependencyInjection.Microsoft.Tests/PipelineOrderingIntegrationTests.cs`'s `ConfigureSharedDependencies` helper - this test's subject is pipeline *ordering*, not NHibernate semantics, and persists nothing. Decide during implementation whether a real (mapping-free) in-memory session is worth the small added setup here, or whether a smaller purpose-built transaction-lifecycle fake (one that doesn't touch the obsolete `ISession.Transaction` surface at all) better fits a test whose subject is ordering rather than persistence. Either way, no more NSubstitute-mocked `ISession.Transaction`.

**Blocked by:** 07 - production code should already read `GetCurrentTransaction()` before these tests are rewritten against its final call shape.
