# 01 - Suppress CS1591 on EF Core generated compiled models

**What to build:** `samples/Interlocutor.Sample.WebApi/CompiledModels/*.cs` (EF Core's compiled-model generator output) currently trips CS1591 (missing XML doc comment) even though the files are generated, not hand-authored. Stop the warning from firing on these files without hand-writing docs that would be overwritten on the next model regeneration - either fix why the generator's output isn't being recognized as generated code (missing `<auto-generated>` header, or the files aren't excluded from doc-analysis) or suppress CS1591 for that directory/project the way generated code is normally handled elsewhere in the repo.

**Blocked by:** None - can start immediately.

**Status:** done

- [x] `dotnet build` no longer reports CS1591 for anything under `samples/Interlocutor.Sample.WebApi/CompiledModels/`
- [x] The suppression is scoped to generated files only - it does not silence CS1591 for hand-written code elsewhere in the sample or in `src/`
- [x] Re-running EF Core's model-compilation generator (if applicable) does not reintroduce the warning

## Comments

Fixed via a scoped `.editorconfig` section (`[samples/Interlocutor.Sample.WebApi/CompiledModels/**.cs]` setting `dotnet_diagnostic.CS1591.severity = None`), matching the existing "C# Autogenerated code" pattern already in the file for `**/obj/**,**/bin/**`. Path-scoped rather than file-content-scoped, so it survives regeneration and does not touch hand-written code.
