# Best Practices Reference

Status: **not started**. Tracked as issues under `.scratch/best-practices-reference/issues/`.

## Original request (paraphrased from a design conversation)

> Create a "best practices" reference.

## Decisions from the grilling session

- **Audience**: consumers of Interlocutor, not contributors to Interlocutor's own codebase. "How to use Interlocutor well in your app" - not repo coding standards, which `CLAUDE.md` already covers reasonably well.
- **Location**: `documentation/`, alongside the other consumer-facing docs, subject to that tree's house style (no ADR citations, glossary-linking on first mention, etc. - see `documentation/index.md`'s neighbors for the convention).
- **Scope, deliberately small for now**: a placeholder. The project is not mature enough yet for an exhaustive best-practices doc to be worth writing - this ticket set produces a lightweight starting point, explicitly expected to grow as real usage patterns and pitfalls accumulate. Don't over-invest in this pass.
